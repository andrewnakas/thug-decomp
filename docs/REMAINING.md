# What is left, and why

This page accounts for every game function that is not yet an exact, concession-free match. It is generated by
`tools/remaining_report.py` from the repo itself, the oracle classification (`work/oracle_classes.tsv`), the
directed force-search results and the GameCube pairing (see below). Numbers are code bytes of game functions
(Sony SDK, OpenSSL, GameSpy and libgcc are excluded, as in the progress report).

- **Exact (headline):** 81.21%.
- **Exact including concessions:** 85.23%.
- **Fuzzy** (each non-matching unit weighted by its similarity score): 98.58%.

Every non-matching and concession unit is compiled and run by the functional build
(`tools/build_functional.py`), which boots and plays into the first level in PCSX2 with frames matching the
original (`tools/pcsx2_boot.py ... --route level`; boot the original and the functional build back to back
under the same machine load and compare). So all of this C++ is behaviourally verified, not only scored.

## Why the remaining functions do not match

Every non-matching unit has already been through: the first and second class-B structural sweeps, the oracle
classification, and the directed force search with every accepted force kind (`ga`, `la`, `sched` incl.
replay and two-slot picks, `spill`, `fr`, `lfr`, `reorg`, `cprop`). Most also had a lane rewrite pass with
at most 3 strategies. What is left falls into these residues (from each unit's `blocked:` note where it has
one, else from its oracle class and how close the forced search got):

| Residue | Units | Bytes | What it means |
|---|---|---|---|
| Code shape (instruction multisets differ), undiagnosed | 116 | 177,496 | The game's instruction multiset differs from ours: a source shape nobody has found yet (often a cse/gcse/loop.c consequence of how the original was written). |
| Compiler-internal order the forces do not reach | 40 | 42,952 | Only the order of a compiler-internal decision differs, of a kind the oracle can see but no force kind reaches (PRE reaching-register order, dependents counts, reg-weight keys). |
| Within 4 words under forcing, no forced match | 32 | 22,212 | Forcing gets within 4 differing words but never to 0: usually two interacting decisions, one of them outside the force kinds. |
| gcse / PRE / cse / loop.c decision | 28 | 16,660 | A cse, gcse/PRE or loop.c decision (a hoist, a fold, a copy-propagation) differs. Declining a cprop or PRE was tried; reversing one would bypass legality checks, so it is not offered. |
| Register choice or allocation order | 21 | 13,396 | Register choice or allocation order, in a form `fr`/`lfr`/`ga` cannot express (reload's choice, a preference inherited from another pseudo, float registers in a helper used twice). |
| Stack/spill slot assignment | 4 | 4,184 | Stack slot assignment that the `spill` order force cannot produce (a slot reused vs a fresh one). |
| Instruction scheduling order | 4 | 2,424 | Instruction order: ready-list keys set by sched1 (priority, reg weight, dependents) that a sched2 pick cannot change, or load/store order fixed by dependences. |
| Delay-slot fill (reorg) | 1 | 740 | A delay slot filled from the other thread in a way the `reorg` prediction force does not reach. |
| Switch case value not pinned by the binary | 1 | 668 | A switch's compare tree implies a case value the binary does not pin uniquely; inventing one is forbidden (case-value ruling). |
| Dead or unused value the game keeps | 2 | 380 | The game keeps a value or test whose result is never used; reproducing it would need dead code, which the rules forbid (instruction test, MATCHING_GUIDE.md). |
| Hand-written assembly | 1 | 52 | The game's code is hand-written assembly (no compiler frame): C++ cannot produce it. |

## What was tried that did not help (do not repeat)

- **Other compiler builds** (SN 2.95.3-114/-107, 2.95.2-274/-273a): none matched; every apparent gain was an
  alignment artefact (LAST_MILE.md, "per-function compiler build").
- **Unlisted flags** (`-fforce-addr`, `-fno-cse-follow-jumps`, ...): diagnostics only; the allowed per-file
  flags need neighbour evidence (MATCHING_GUIDE.md).
- **Declaration-context padding**: 0 of 1,296 compiles changed a word (LAST_MILE.md 1.3).
- **The GameCube retail build as a shape reference** (2026-11-14): it pairs with 183 of these units (150 at high
  confidence, 99.7% precision measured on matched functions), and its call skeletons agree with ours almost
  exactly (func_0022F500: 111 of 111 calls in order). In a 10-unit sample of the largest units it revealed no
  structural error in our drafts; the residue is allocation and scheduling, which a different compiler cannot
  inform. Other platform builds (Xbox) are expected to behave the same. A prototype build was not used: internal
  builds are excluded by PROVENANCE.md.
- **Wider force searches**: a beam of 3 with 200 compiles on the units left at 1-4 words found nothing more; a
  `pre` decline kind exists in the oracle as a diagnostic only (no identity check is possible yet).
